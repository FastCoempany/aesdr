# Canon revision: v1.5 — "substantial assets" collective + "operating manual" buyer-facing ban

**Proposed:** 2026-05-28 · From v1.4 to v1.5 · Proposed by Founder

---

## What changes

1. **The buyer-facing collective noun for the seven deliverables becomes
   "substantial assets."**
   - v1.4: *"artifacts"* (which itself retired *"tools"* / *"5 tools"*).
   - **v1.5: *"substantial assets."*** Name the specific assets wherever a
     list reads naturally. The inventory is unchanged and still pinned to
     `utils/content/catalog.ts` — seven assets + the 72-Hour Strike Plan
     end-of-course bonus (gated on all twelve lessons complete):
     - AE/SDR Alignment Contract (3.3)
     - Manager Archetype Map (4.1)
     - Async Cadence Template (4.3)
     - The "I Don't Know" Framework (6.3)
     - CRM Survival Guide (9.1)
     - Time Reclaimed Calculator (9.2)
     - ROI & Commission Defense Tracker (10.1)
     - *Bonus:* 72-Hour Strike Plan (`bonus-72-hr-strike-plan`)

2. **"Operating manual" is banned as literal buyer-facing product copy.**
   It remains (a) the canonical affiliate/marketing tagline — *"the operating
   manual, not the motivation engine"* — and (b) the internal editorial
   north-star frame (base canon §2). The ban is **surface-scoped**, not
   absolute: it applies to the live product UI (`app/**`, `components/**`) and
   buyer-facing lesson HTML, and nowhere else.

3. **Both rules are now mechanically enforced** (see "Mechanical enforcement"
   below), so neither term can creep back into buyer-facing surfaces unnoticed.

## Why

- **"Takeaway" was founder-banned**, which made v1.4's "takeaway artifacts"
  stale on its face. "Artifacts" alone read thin/archaeological for a thing the
  buyer is meant to *use*; bare "assets" read generic. "Substantial assets"
  names weight without a manufactured concept and survives the read-aloud test.
- **"Operating manual" reads like a static book/PDF in-product.** Founder
  direction (2026-05-27, commit `ee985d4`): in the product UI it implies a
  bound document rather than the work. Describe the function instead — *"how
  the job works,"* *"the whole job, in order."* As a *tagline* and as the
  team's editorial frame it still earns its place; it just can't be the literal
  string a buyer reads inside the product.
- **The May 2026 audits showed positioning language leaks** (the wedge, the
  operating system). Mechanical enforcement is how we stop the leak rather than
  re-catching it by hand every month.

## Supersedes

- **§14 / vocabulary pack v1.4** (`2026-05-27-tagline-pack-v1.4.md`): its
  "artifacts" collective is replaced by "substantial assets." v1.4's §14
  tagline (*"12 courses. Same you — way, way better."*) is **unchanged** and
  carries forward. v1.4 is retained as historical record.

  `design-canon/` and `design-canon-seed/` snapshot trees.

## Mechanical enforcement

- **ESLint** (`eslint.config.mjs`, `CANON_BLOCKLIST`): added `operating manual`.
  The `no-restricted-syntax` rule is already scoped to `app/**` + `components/**`
  (string literals, JSX text, template literals), which is exactly the
  buyer-facing product surface where the phrase is banned. No carve-out is
  needed because the rule never runs against the affiliate-kit / docs trees.
- **`scripts/canon-check.mjs`** (markdown / HTML / text the linter can't reach):
  added `operating manual` with a new per-pattern `allowIn` mechanism. `allowIn`
  exempts a *single* pattern in named path trees while every other blocklist
  entry still runs there. For `operating manual` the allowed trees are
  `docs/affiliate/`, `docs/content/`, `content/affiliate-kit*`,
  `content/aesdr-internal/`, `public/mockups/`, `tools/rendered/` — i.e.
  everywhere the tagline is canonical. Buyer-facing lesson HTML and stray docs
  stay gated.
- **"substantial assets"** is the approved term and is therefore *not* gated;
  the buyer-facing migration off "takeaway artifacts" is what these gates
  protect by catching the banned phrasing if it returns.
